# Android TV 超级飞鼠设计

> 本设计包含首版电视遥控器，以及后续补充的“超级飞鼠”交互。用户确认：普通触控继续使用 HTTP；只有进入陀螺仪空中飞鼠时，才按需启动局域网 HTTPS，并显示首次证书信任指引。

## 意图

把 AirMouse 从“手机控制电脑”扩展为“手机控制 Android TV”。电视是输入接收端，手机浏览器承担触摸板、遥控快捷键、键盘及整段文字输入。

## 目标

- 用户可在 Android TV 上安装并运行配套 App。
- TV App 在局域网提供手机控制页和 WebSocket 指令通道，使用二维码携带本次启动的配对令牌。
- 手机控制页支持相对指针移动、单击、双击、拖拽、滚动、常用快捷键、按键输入及整段文字发送。
- TV 端使用 AccessibilityService 派发触屏手势，绘制指针覆盖层；对可访问节点优先使用节点操作。
- 通过 AccessibilityService 支持 Back、Home、方向/确认导航；方向键在系统提供对应 Global Action 时直接触发，否则尝试基于无障碍节点焦点移动。
- 输入法作为整段文本输入的主要路径，在输入框获得焦点时调用 InputConnection.commitText；AccessibilityNodeInfo.ACTION_SET_TEXT 作为可用节点的备用路径。
- 无障碍服务首次配置由用户在电视系统设置中显式启用；App 提供清晰的引导与状态。
- 保持现有桌面服务工作方式；电视模式是独立 Android 工程，不把 Android 输入逻辑混进桌面 pyautogui/pynput 服务。

## 非目标与限制

- 普通 Android App 无法保证向所有 TV App 派发真正的全局原生鼠标 HID 事件。第一版通过无障碍手势和屏幕指针实现鼠标式交互；只支持 D-pad 的界面可能需要切换 D-pad 模式。
- 不做蓝牙 HID、ADB、root 或系统签名输入注入。
- App 不承诺电视应用都开放可访问的输入节点；目标字段不支持无障碍设置文字时，用户启用 AirMouse 输入法后由 InputConnection 发送。
- 首版仅面向 Android TV / Google TV Android 7.0（API 24）及以上设备，实际兼容范围仍需真机验证。
- 控制和配对信息只在局域网传输；随机配对令牌用于限制同网段未配对设备访问。普通触控不启动 TLS；用户主动启用空中飞鼠时，电视才按需提供本地 HTTPS/WSS 与首次证书信任说明。它不提供互联网远程控制或云端中继。

## 架构

- 仓库分为并列的 `desktop/` 与 `android-tv/` 子项目。现有 Python 电脑端源码、网页资源、配置、锁文件、测试和打包脚本迁入 `desktop/`；Android 电视端是独立 Kotlin/Gradle 工程。
- 根目录提供两端总览；电脑端安装、运行和打包命令从 `desktop/` 子项目运行。
- TV App 实现电视 Activity、局域网 HTTP/WebSocket 服务、AccessibilityService 和 InputMethodService。
- TV App 通过二维码把 `http://<tv-ip>:<port>/?token=<random-token>` 呈现给手机；网页与 WebSocket 使用同一主机、同一端口。
- 手机页是独立于现有 Socket.IO 的轻量 WebSocket 页面，消息采用 JSON：`move`、`click`、`drag_start`、`drag_end`、`scroll`、`key`、`text`、`status`。
- AccessibilityService 维护指针坐标和覆盖层，将点击/拖拽/滚动转成 GestureDescription；Home/Back/D-pad/确认优先使用 Android Global Action，低版本使用可访问节点焦点候选作为方向导航回退。
- InputMethodService 在当前输入连接存在时提交整段文字和回车；输入法未激活时，接收端查找当前输入焦点节点并尝试 ACTION_SET_TEXT。
- 新服务采用独立的控制处理器和状态对象，便于将桌面与 TV 输入实现分开维护。
- 移动电脑端文件时同步修正脚本/文档的相对路径，资源仍以 `desktop/` 为根；电脑端事件处理逻辑保持原样。

## 本次实现的默认决策

- 手机无需安装原生 App；电视 App 自行提供本地网页。
- 默认 HTTP + WebSocket，局域网内用随机令牌配对；每次 App 服务重新启动时生成新令牌。
- 无障碍服务是电视全局控制所需组件；App 使用 Android 系统设置页引导用户启用，而不是静默启用。
- 首版优先保证触控板指针、点击/双击/拖动、滚动、Back/Home/D-pad、键盘快捷输入和整段文字发送。
- Android 方向键 Global Action 仅在平台提供时调用；旧系统使用 accessibility node 导航并在不可用时给出明确反馈。
- 不改变现有 Python 桌面控制页面和事件处理；只调整其所在目录及配套入口路径。

## 验收标准

- Android Studio 可同步并构建 Debug APK。
- TV App 显示局域网地址、配对二维码、连接状态和无障碍/输入法配置入口。
- 扫码后手机页可以连接，并发送协议中列出的控制操作。
- 未提供正确令牌的 WebSocket 请求被拒绝。
- AccessibilityService 收到指针/点击/双击/拖拽/滚动/系统快捷键后调用对应 Android API；服务关闭或电视应用不支持相应输入时，界面显示未启用/不支持状态。
- 输入法通过 InputConnection 提交手机端整段文字和回车；当前焦点暴露 ACTION_SET_TEXT 时可作为备用输入路径。
- README 提供安装、首次授权、连接和兼容限制说明。

## 超级飞鼠交互扩展（2026-10-19）

### 目标与体验原则

- 让手机在日常使用时像一只简单、趁手的电视遥控器；新能力按当前任务出现，不在首页堆成控制面板。
- 保留 HTTP 下的触控、键盘、快捷键和已有配对流程。用户主动切换到“空中飞鼠”时才引导启用 HTTPS 和手机传感器权限。
- 同一电视最多允许现有上限 4 部手机连接。多人同乐是可主动开始和结束的临时活动，不干扰普通遥控。
- 所有主要按钮满足手机触控尺寸，适配窄屏、安全区域和横竖屏；在真实浏览器中核实首页与入口展开后的布局。

### 手机端信息架构

控制页首屏仅突出：电视连接状态、全屏按钮、触控/空中模式切换、大触控板、轻量点击/音量快捷操作。全屏按钮使用浏览器 Fullscreen API，并提供不支持全屏时的明确反馈。

屏幕底部提供四个清晰入口：

- **遥控**：触控板/空中飞鼠、方向导航、常用按键；键盘输入作为可快速打开的独立面板，包含“发送文字”和“发送并搜索”。
- **场景**：展示已保存的追剧按钮。创建场景时选择电视已安装的可启动 App、输入搜索词，并选择发送后是否回车/播放；电视端按顺序执行启动、等待、提交文字和可选播放操作。场景保存在手机本地。电视只在目标 App 已位于前台且暴露可编辑焦点时发送片名；未就绪时停止后续输入并提示用户先进入该 App 的搜索框。
- **同乐**：提供“抢答”和“选片投票”两个开始动作。发起者可写问题或候选片名；其他已连接手机收到同步活动页后点选/抢答。电视画面同步显示题目、倒计时、抢答赢家/投票结果。活动结束回到原遥控界面。
- **设置**：三种清晰可辨的电视光标皮肤预览；点击音效、手机轻震开关；空中飞鼠灵敏度和 HTTPS/传感器状态。外观和反馈设置按手机本地保存，光标皮肤同时发送到电视。

首页视觉沿用电视端的石墨灰与 AirMouse 薄荷绿身份，不套营销型卡片网格：

```text
┌ AirMouse · 已连接电视                    ⛶ ┐
│  [ 触控板 ]  [ 空中飞鼠 ]                   │
│                                             │
│               大面积触控区                  │
│                                             │
│             点击 · 音量快捷                  │
├ 遥控 ─── 场景 ─── 同乐 ─── 设置 ┤
└─────────────────────────────────────────┘
```

设计 token：石墨底色 `#101316`、面板 `#191F23`、薄荷绿 `#76E7AC`、正文 `#EEF5F2`、辅助文字 `#9AA9A4`；沿用系统无衬线字体，突出大触控区和手指可达的底部入口。避免长页面和同时展示全部能力。

### 空中飞鼠与按需 HTTPS

- 触控板是默认输入，陀螺仪事件在用户切换模式前保持关闭。
- 用户点击“空中飞鼠”后，网页显示一句说明并向电视 HTTP 控制端请求按需启动 HTTPS 服务。电视端提供可信任步骤和打开 HTTPS 控制页的链接；完成信任后，手机从 HTTPS 页面连接 WSS，用户再次点击后才请求传感器权限并开始读取方向事件。
- 首次信任指引按 iOS Safari 与 Android Chrome 分别说明；保留返回 HTTP 触控板的通路。HTTPS、证书信任、浏览器 API 或传感器权限任一不可用时，明确解释原因并允许继续触控板控制。
- 方向控制以首次传感器读数为校准基准，启用死区和可调灵敏度；切回触控板立即停止监听传感器。
- HTTP 与 HTTPS 页面属于不同浏览器 origin；切入安全页面时用不发送给服务端的 URL fragment 迁移手机本地场景与偏好，页面读取后立即移除 fragment。
- 不因普通用户打开遥控器就启动 HTTPS、不默认弹出传感器授权，也不在页面后台时持续读取传感器。

### 场景能力边界

- TV 端只暴露已安装且可启动的应用列表，并只执行协议允许的应用启动、文本输入、回车、播放/暂停步骤。
- App 内搜索框的焦点和“搜索后自动播放”行为由第三方 TV App 决定；AirMouse 对此提供尽力而为的顺序动作，不承诺跨所有视频 App 都能稳定自动播放。UI 应避免保证不可控的跨 App 行为。
- 用户可编辑和删除场景。首次使用提供一个“打开 App 并搜索”引导，不要求先了解宏/脚本概念。

### 多人活动

- 继续采用现有单电视配对令牌和最多 4 个 WebSocket 客户端，不新增账号或云端房间。
- 当前第一个发起活动的人拥有主持控制；电视服务把玩家身份绑定到已配对 WebSocket，为房间计时、记分、同步主持问题和投票候选，并拒绝活动之外的游戏命令。
- 抢答先提供问题文本、3 秒倒数、所有玩家一个大按钮；最先到达电视的有效抢答获胜，电视和手机显示获胜玩家并结束本轮。
- 投票候选由主持人在手机端输入，参与者每人一票，电视显示实时票数和最终结果；主持人可重开一轮或结束活动。
- 断线玩家可在同一配对页重连后回到活动状态；主持人短暂断线有 15 秒重连宽限，仍未回来时移交给在线玩家，无人在线则结束活动；新活动开始时清理上轮结果。

### 验收标准补充

- 375×812 和至少一个窄屏视口下，首屏不需要滚动即可触控、点击、切换模式和访问底部导航；场景创建、投票、设置内容按需展开并可关闭返回。
- 全屏按钮可进入/退出全屏；不能使用 Fullscreen API 的浏览器仍保留完整可操作布局。
- 未启用 HTTPS 或传感器权限时，手机仍可正常使用 HTTP 触控；仅选择空中飞鼠时才显示 HTTPS/信任流程；成功后设备方向变化产生有界相对指针位移，关闭/离开空中模式后停止监听。
- 4 部配对手机可同步进入同一抢答/投票活动，抢答赢家唯一，投票计数一致；活动结束后原有遥控恢复。
- 场景能启动所选 App、等待设定时间、发送搜索文字及所选按键；不支持启动/输入时手机收到明确提示。
- 三套光标皮肤在 TV 覆盖层可辨识；点击音效与震动可独立开关且按手机保存。
