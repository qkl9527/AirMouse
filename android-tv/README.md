# AirMouse Android TV

Android TV 端是一个独立 Kotlin 工程。电视安装并运行 App 后，手机使用浏览器扫码打开配对页，无需安装手机端 App。

## 目前支持

- 手机触摸板控制电视屏幕指针，单击、双击、拖动和双指滚动。双指默认上下滚动，打开触摸板左上角的“双指左右”开关后改为左右滚动；会记住选择，全屏触摸板内也能切换。
- 手机控制页提供全屏入口，常用遥控操作集中在首屏，方向键和键盘等按需展开。
- 手机页面分为遥控、场景、同乐和设置入口，避免把所有控制项堆在一个长页面。
- 手机方向传感器飞鼠按需切换：普通触控使用 HTTP；首次进入空中飞鼠时才启动电视本地 HTTPS/WSS，并引导信任电视证书。
- HTTP 与 HTTPS 的浏览器存储彼此隔离；切换到空中飞鼠时，页面会安全迁移已保存的场景和遥控偏好，让两种控制模式保持一致。
- 追剧场景可以保存电视 App、片名和搜索/播放步骤；发送片名前会核对目标 App 是否在前台且提供可编辑的搜索焦点。
- 同乐支持最多 4 部手机共用的电视端抢答和选片投票，赢家与票数由电视统一记录。
- 设置可选电视指针样式、手机点击音效/震动和陀螺仪灵敏度；不支持的浏览器能力会保留静默/触控操作。
- 返回、主页、方向键、确认、音量和静音快捷键；手机页可保存四个自定义快捷键。
- 手机键盘默认覆盖电视输入框的整段文字，也可切换为在当前光标处插入；支持左右移动文字光标、删除光标前的字符（有选区时删除选中部分）、回车搜索和空格。发送后立即反馈，电视在独立的有序队列内执行输入与搜索；失败或断线时可找回未确认文字，不依赖七秒倒计时判断成败。
- 电视端显示配对二维码、控制服务状态和当前手机连接数。

电视端通过 Android `AccessibilityService` 派发系统触屏手势并显示屏幕指针。普通 App 不能注入真正的全局鼠标 HID 事件，所以只支持 D-pad 的电视界面仍应使用手机页中的方向键和确认。部分 TV App 不接受无障碍手势或文字填充，兼容性需要在目标电视和 App 上确认。

受 Android 手势接口的轨迹提交方式影响，触摸板拖动会在手指抬起后按完整轨迹派发；屏幕指针仍会随手机手指实时移动。

## 构建 APK

需要 Android Studio 或 Android SDK、JDK 17 及以上版本。用 Android Studio 打开本目录，或在终端运行：

```bash
./gradlew :app:assembleDebug
```

Debug APK 输出到：

```text
app/build/outputs/apk/debug/app-debug.apk
```

把 APK 安装到 Android TV / Google TV（Android 7.0 / API 24 及以上）：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 自动构建与发布

仓库已提供 GitHub Actions Workflow：主分支 Android 相关提交和 Pull Request 自动生成 Debug APK；推送 `airmouse-tv-v1.0.1` 这样的版本标签后，自动构建签名 Release APK 并上传 GitHub Releases。

正式发布前需一次性配置固定签名的四项 GitHub Secrets。完整的本地打包、签名配置、提交与版本标签命令见 [APK 打包与发布说明](RELEASING.md)。

## 首次设置与配对

1. 电视和手机连接同一个 Wi-Fi 或局域网。
2. 在电视启动 AirMouse，选择“开启 AirMouse-电视控制服务”，并在 Android 系统提示中允许该无障碍服务。
3. 回到 AirMouse 首页。电视会显示配对二维码和手机访问地址；手机扫码后即可连接。
4. 使用触控板、方向键或快捷键控制电视。
5. 要从手机向电视搜索框输入整段文字，在 Android 系统的“输入法”设置里启用“AirMouse-手机键盘输入”，并将其设为当前输入法；随后在手机页键入并点“发送并搜索”。
6. 首次使用空中飞鼠时，手机页会按需启用电视 HTTPS 服务，并提供证书下载和信任说明；安装前请核对手机显示的 SHA-256 指纹与电视屏幕一致。完成系统信任后返回页面并继续。普通触控遥控不要求安装证书，也不会启动 HTTPS。

Android TV 厂商的系统设置菜单名称可能不同。若电视 App 无法直接打开对应设置页，请从电视的“设置 → 辅助功能”或“设置 → 键盘/输入法”手动进入。

## 网络与权限

- 手机网页由电视 App 在本地提供，默认使用 TCP 8765 端口；端口被占用时会自动选择空闲端口。
- 每次电视控制服务重新启动都会生成新的随机配对令牌。二维码地址只对本次令牌有效。
- 普通页面和控制命令通过局域网 HTTP/WebSocket 传输；空中飞鼠额外按需启动本地 HTTPS/WSS，证书根私钥留在电视 App 私有存储。服务不提供互联网远程访问或云端中继，请只在可信的家庭/办公局域网配对。
- 每次控制服务启动都会重新生成配对令牌。空中飞鼠的本地证书身份会保存在电视上；电视局域网 IP 变化时会重新签发匹配新地址的服务证书，手机可能需要重新信任。
- Android 必须由用户在系统设置中显式启用无障碍服务和（文字输入时）输入法；应用不能代替用户授予这些权限。

## 当前限制

- 手势和光标基于 Android 无障碍 API，不是蓝牙鼠标；某些流媒体或系统界面会屏蔽手势。
- Android 13 及以上优先使用系统方向键全局操作；较早版本使用可访问控件的空间位置尝试移动焦点，遇到不暴露无障碍节点的页面可能失败。
- 整段文字优先通过 AirMouse 输入法的 `InputConnection` 提交；输入法未选中时，备用的无障碍文字填充取决于目标输入框是否支持 `ACTION_SET_TEXT`。
- 文字光标移动与删除针对电视当前输入框；建议启用并选中 AirMouse 输入法。无障碍备用编辑还要求 App 提供可编辑文本、选区信息及 `ACTION_SET_SELECTION`；缺少这些能力时会提示，不会猜测光标位置。密码输入框的局部编辑只通过输入法完成。
- 使用其他输入法时，会跨窗口定位应用的输入焦点，并跳过第三方键盘窗口；部分 TV App 的定制搜索框不开放可编辑节点或选区，无法保证通用的插入、删除和光标移动。手机页会识别旧版电视服务，避免等待旧服务未实现的结果回执。
- 视频 App 是否在打开后自动聚焦搜索框由 App 自己决定。场景会检查目标 App 和可编辑焦点，未就绪时停止后续输入并提示用户先进入搜索；“搜索后开始播放”仍取决于第三方 App 对遥控播放键的支持。
- iOS/Android 对用户安装的本地 CA 证书都可能显示系统信任提示；不同系统版本的证书安装流程略有差异。若不想更改手机证书信任设置，可继续使用普通触控遥控。
- 不同电视厂商的无障碍权限、输入法策略、分辨率和系统栏布局各异。目前已完成 Debug APK 构建，设备端的实际手势和输入兼容性仍需真机验证。
